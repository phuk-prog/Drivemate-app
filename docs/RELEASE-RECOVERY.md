# Release recovery and changelog
Keep a verified AES-256 encrypted last-known-good APK ZIP in an owner-controlled backup, together with the commit, version, certificate digest, map-lock.json and archive SHA-256. Existing raw APKs must not be restored to GitHub. Before promoting any candidate, test an update from the previous signed version, validate navigation on a physical device, and record a reviewed acceptance decision.
If a candidate fails, stop promotion; restore the last-known-good code and exact map pins in a new branch, advance the version with tools/bump_release_version.py, rerun all gates, then sign and encrypt with the existing certificate. Android may refuse an older version code; do not bypass downgrade safeguards. Map data refresh must retain immutable earlier releases. Never claim road validation from CI alone.
For a release changelog use git log --first-parent PREVIOUS_GOOD_COMMIT..HEAD and review user-visible changes and known limitations. Do not publish raw APKs or secrets. A recovery release requires explicit owner approval.
