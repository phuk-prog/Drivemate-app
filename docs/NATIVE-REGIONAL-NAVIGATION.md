# DriveMate native regional navigation candidate

This stacked candidate builds on PR #51, not on Claude's parallel refactor. Main and existing signed version are unchanged. Native-only app selection ignores stored external credentials, uses local graph search and route calculation, and does not fall back to TomTom or a hosted router when coverage is missing. Existing TomTomApi DTO names and unused legacy adapters remain for compatibility with the UI/tests; they are not proof that external routing is used. The packaged Cheadle/Stockport map is the initial verified coverage, NOT all UK regional downloads.

The native candidate generates turn instructions from exact graph way transitions, legal outgoing choices and path bearings; no invented roundabout exit numbers, lanes, signposts, destination entrances or live traffic. Explicit nonconditional source limits only. Matching geometry, bounded memory, GPS and the existing release gates remain. Node snapping is bounded but not a substitute for production map matching. Unit tests and offline instrumentation exercise native route conversion, road search, source way identity and coverage failure without a provider. This is not a proof of live driving or full postcode coverage. Native driving start remains deliberately blocked by NavigationStartPolicy until actual manoeuvre, map matching, rerouting, roundabout, motorway, restriction, accessibility and physical-device acceptance pass. Incomplete regional GitHub archive publishing and ingestion, native reroute and full GPS-guidance acceptance still block a native production APK. No hosted services or release signing.

Do not merge this branch over PR #52 or change provider fallback on the working main release. Review and reconcile once the native candidate has sufficient coverage and end-to-end evidence.

## Owner's DriveMate-first architecture rule
DriveMate owns routing, search, matching, ETA, manoeuvres, road restrictions, camera, map source and style, rendering control and voice guidance. GitHub releases supply data; no hosted routing or provider base map. OpenStreetMap is the underlying licensed dataset. MapLibre is currently the open-source GPU rendering library and osmdroid remains as a hidden offline compatibility object; these are dependencies, not proprietary map providers or fully DriveMate-written rendering engines. Replacing the libraries themselves with a custom GPU renderer is separate work, not claimed here.

Day and night styles now contain only DriveMate world and UK sources; external base styles, raster tiles, hosted building detail and external search/route fallback are forbidden even if a key exists. Native free-drive context reads the regional pack and converts E6 to E7 exactly for the existing conservative road matcher. The only optional external enhancement is separately consented TomTom area incident markers (default off, distinct key, labelled source, time-limited; no provider geometry used as route closures or instructions, no changes to route, limits or ETA). Owner must confirm licence entitlement before use. No new provider requests performed as part of this change. Coverage and driving acceptance remain outstanding. CI checks actual style assets and core call sites.

## Original DriveMate renderer — first independent implementation
NativeMapProjection, NativeMapScene and NativeMapView are DriveMate-owned code using Android Canvas drawing primitives. No MapLibre, osmdroid or external style objects in these classes. They implement Mercator, rotation, affine tilt (not true 3D), view culling, road/building/land/water layers, bounded labels, exact route geometry, progress and turn arrows, vehicle/destination, gestures and day/night colours. Source way/node identity is independently verified before a scene is created. Settings now opens the original renderer preview. Offline emulator tests render actual regional data at 14/17/19/21 day/night and capture screenshots; prior GPU tests are retained. The legacy renderer remains in MainActivity for the moment; replacement is not complete. World/UK MVT decoding, region streaming, high-performance GPU batching, full road furniture, 3D, accessibility, live camera/gesture integration and release acceptance remain. Android OS, graphics and standard libraries are platform dependencies; OSM remains licensed source data. No APK signing.
