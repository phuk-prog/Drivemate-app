# Private APK and service distribution
Public source remains visible and forkable under GitHub terms. Anyone may technically build or alter public code; signing and client checks do not prevent that. Official APK distribution must be access controlled.

## Owner setup (required before signing)
1. Create a **private standalone** repository, e.g. DriveMate-private-delivery, with only approved collaborators. Do not create a public fork for signing. Copy the reviewed source at an exact commit into the private repository; verify the commit and keep provenance. Preserve the existing signing key in a secure offline backup.
2. Configure the private repository's protected drivemate-release environment, main-only branch rules, required reviewers, and environment-scoped existing signing secrets. Do not create new signing identities or expose private keys. Remove the repository-level signing secrets from public repos only after the private setup is verified. Disable legacy signing workflows on public branches; restrict environments and secrets so historical workflows cannot sign.
3. Run validation, emulator replay, and signing in the private repository. Verify package, version and certificate. Distribute only via private Actions artifacts or an authenticated download service. Do not copy APKs into public git history, Releases, or Actions artifacts. Audit historical public artifacts/releases and remove APK assets after preserving owner backups; copies already downloaded cannot be recalled.
4. For hosted services, use TLS and per-user authorisation at the trusted server/proxy, short-lived revocable credentials, rate limits and minimal logs. Do not embed a shared secret in public source or the APK. Owner must select and configure identity provider, API host, approved users and credential issuance. Keep routing engine and intelligence bound to loopback behind the authenticated proxy.
5. For official offline app activation, require a signed, time-limited entitlement bound to the approved account/device, with a private signing key held only on the server. Define safe expiry behaviour: never interrupt active navigation; disable new sessions after safe termination. Public source can be modified to bypass client checks; server enforcement remains essential. No activation system is deployed by this document.
6. Obtain explicit EULA acceptance and retain private consent records; provide required privacy notice and third-party notices. Do not claim UK trademark registration or copyright ownership of third-party data.

## Existing access
Public GitHub artifacts are readable by signed-in GitHub users with repo read access; signed APKs are not confidential. Audit prior branches, workflow artifacts, releases and service URLs. No data or artifacts are deleted automatically. Map ODbL data remains available under its licence.
